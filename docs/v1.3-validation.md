## 동적 시나리오 결과

### 1. 기본 Colibri

- TPS: 1.317
- Average TPOT: 759.2ms
- Peak physical memory: 65.0GB
- Swap-out: 0GB
- Peak observed DRAM BW: 22.76GB/s
- Observed storage BW: 8.31GB/s

기본값은 Storage-bound이며 DRAM 40→80GB/s 변화가 TPS에 영향을 주지 않았다. 병목이 이미 SSD 경로에 있기 때문이다.

### 2. DRAM-bound 유도 시나리오

SSD BW를 50GB/s로 높인 상태에서 DRAM BW만 변경했다.

| DRAM BW | TPS | TPOT | DRAM Stall/token |
|---:|---:|---:|---:|
| 5GB/s | 0.298 | 3357.8ms | 1172.5ms |
| 10GB/s | 0.596 | 1678.9ms | 524.9ms |
| 20GB/s | 1.191 | 839.5ms | 201.1ms |
| 40GB/s | 1.798 | 556.2ms | 0ms |

DRAM BW가 2배가 될 때 DRAM-bound 구간에서는 TPS가 약 2배 증가하고, 다른 병목으로 전환되면 증가율이 포화되는 방향을 확인했다.

### 3. Colibri Memory 64GB vs 128GB

압력 시나리오: 20K context, anonymous Expert Cache, Swap trigger 75%.

| Memory | TPS | Swap Start | Swap-in | Swap-out | Final State |
|---:|---:|---:|---:|---:|---|
| 64GB | 1.108 | Token 2 | 7.82GB | 9.46GB | THRASH |
| 128GB | 1.323 | 없음 | 0GB | 0GB | NORMAL |

Memory 증가가 Swap을 제거하고 TPS를 회복시키는 방향을 확인했다.

### 4. AFM 3 기본값

- Effective TPS: 23.64
- Steady TPS: 23.81
- Boundary TPOT: 61.3ms
- Swap: 0GB

### 5. AFM 3 KV pressure

32GB Unified Memory, 50K context, 8 output token.

- TPS: 1.132
- Swap Start: 초기 pressure 단계
- Swap-in: 25.50GB
- Swap-out: 28.69GB

AFM Shared/Current Routed weight는 pinned 상태로 유지되고 KV working set이 Swap traffic을 생성하는 것을 확인했다.

## 물리 보존 검증

- Expert demand, prefetch, AFM window read, Swap-in, Swap-out이 동일 StorageResource timeline을 사용한다.
- Swap write는 설정된 write bandwidth ratio를 적용한다.
- DRAM floor 적용 후 `dramTraffic / TPOT <= configured DRAM BW`를 만족한다.
- Swap capacity를 넘는 anonymous Expert page-out을 제한한다.

## 남은 한계

- 실제 OS page replacement, page size, dirty/clean tracking을 재현하지 않는다.
- macOS compression, Linux zswap/zram, Windows pagefile 정책 차이는 집계 parameter로 추상화한다.
- DRAM traffic은 weight/KV/I/O 기반 aggregate estimate다.
- GPU VRAM bandwidth 및 VRAM oversubscription은 별도 모델이다.
- Swap-out은 background queue 점유로 반영하며, 실제 scheduler 우선순위는 모델링하지 않는다.
