# v1.6.1 Correctness Contract

## Status

This patch candidate remains **Unvalidated Alpha**. It is suitable for controlled, relative sensitivity experiments. It is not a calibrated predictor of absolute hardware TTFT, TPOT, throughput, or capacity.

## Decimal SI units

Every UI/configuration field labeled `GB`, `MB`, or `KB` uses decimal SI units:

- 1 GB = 1000 MB
- 1 MB = 1000 KB
- 1 GB = 1,000,000 KB

Binary units are not implicit. A future binary-valued field must be labeled explicitly as `GiB`, `MiB`, or `KiB` and must not reuse a decimal field.

The contract covers host/VRAM/cache capacities, Expert sizes, prefetch budgets, and KV bytes per token. The 3% Expert packing overhead is applied after converting the raw Expert size to decimal GB.

Accepted positive bandwidth ratios, PCIe/DRAM rates, and prefill speedups are modeled at their exact configured values. `EPS` is used only as a divide-by-zero guard.

## Metric populations

- **TTFT:** request arrival through the first completed token, including blocking initial selection, reads, patching, compression, and swap dependencies.
- **TPOT percentiles:** completed decode tokens only; the first-token interval is excluded.
- **Storage/token:** storage traffic generated during decode divided by completed tokens. Startup, prefill, and predecode swap traffic is reported separately. Observed decode bandwidth uses the longer of token completion time and completion of decode-issued background I/O, so unfinished writes cannot exceed configured device bandwidth by construction.
- **Scenario artifacts:** top-level OOM results are rejected rather than exported or imported as completed scheduler populations. Scenario `Storage/token` uses scheduler first-token plus decode SSD work divided by scheduler-completed tokens.
- **Aggregate TPS:** completed tokens divided by the completed-event wall-clock interval for every concurrency value, including one.
- **Peak allocation demand:** pre-policy high-water mark of requested bytes, which may exceed host capacity before reclaim admission.
- **Peak physical memory:** high-water mark of admitted resident bytes after pressure admission. It cannot exceed host capacity; pending page-outs remain resident until their writes complete, and allocations that would cross the hard limit block for reclaim.

## Concurrency ownership

Model weights and completed-request Expert cache state are globally shared. A later request inherits cache residency committed by requests that completed before its arrival. Overlapping Colibri misses are conservatively modeled independently (no optimistic in-flight miss coalescing), and completed cache states are merged within each configured LRU capacity. KV and transient request state are request-owned. DRAM, SSD, PCIe, compression/decompression CPU, compute, and patch resources are shared scheduler resources.

A direct serving request population must equal `config.conc`; mismatches fail closed.

## AFM DRAM scope

The current AFM DRAM bound includes active weights, configured KV touch, SSD landing writes, swap traffic, and compression traffic. Patch-materialization read/write bytes are explicitly excluded because the simulator does not yet expose a validated physical byte model for that operation. Results expose this exclusion rather than silently treating it as zero measured traffic.

## Reproducibility fence

Scenario schema `moe-ssd-sim/v4` and Run IDs are fenced by model, package, commit, and build identity. Imported artifacts are replayed and rejected when provenance, configuration, request population, persisted metrics, or derived Advisor evidence do not match.

Published browser assets must be produced with `npm run build:release` from a clean release commit. The builder writes the exact 40-character Git SHA and a `release/v<package>+<sha>` build identity into `build-info.js`; both the main document and simulation/replay Workers load that file before simulator code. Source-tree fallback provenance is development-only and is not a releasable artifact.

The release builder derives identity directly from Git `HEAD`, forbids commit overrides and arbitrary output paths, and reads a fixed browser-runtime allowlist from committed Git objects. Tests, tooling, ignored files, and files outside that allowlist are not copied into `dist/`.
