## 수정한 일관성 결함

1. Pinned Expert가 prefetch 후보에서 제외되지 않던 문제
2. 호출부와 storage resource에서 QD를 각각 나누던 문제
3. DRAM/Pinned/Page/Swap source가 PCIe 전송 후 VRAM LRU에 들어가지 않던 문제
4. Prefill이 cache를 변경하지 않고 `prompt / 28 tok/s` 상수에 의존하던 문제
5. RAM/VRAM 용량과 Expert cache 설정이 독립적이던 문제
6. Swap-in byte가 load-write와 swap traffic 양쪽에 들어가던 문제
7. Aggregate TPS가 scheduler throughput처럼 보이던 표시 문제
8. 매우 낮은 Prefetch precision에서 후보 생성이 Expert 수를 넘겨 종료되지 않을 수 있던 문제
9. Manual VRAM cache의 실제 사용량이 물리 VRAM을 넘어도 보고되지 않던 문제

## 방향성 회귀 시나리오

각 시나리오는 다른 경로를 충분히 빠르게 설정해 대상 경로가 bottleneck이 되도록 격리했습니다.

| 시나리오 | 검증 결과 |
|---|---|
| SSD-bound prefill | SSD BW 증가 시 TTFT 감소 |
| PCIe-bound prefill | PCIe BW 증가 시 TTFT 감소 |
| DRAM-bound unified execution | DRAM BW 증가 시 TTFT 감소 및 TPS 증가 |
| Auto RAM placement | RAM 증가 시 DRAM Expert cache 증가 및 prompt SSD reload 감소 |
| Auto VRAM placement | VRAM 증가 시 VRAM Expert cache 증가 및 prompt PCIe reload 감소 |
| Compute-bound prefill | Attention latency 증가 시 TTFT 증가 |
| Fully pinned Experts | Demand/Prefetch Expert read 0 |
| Eight reads at QD=2 | 정확히 4 latency waves |
| Swap-in accounting | Colibri와 AFM 모두 DRAM traffic에 1회만 포함 |

## 기본 sweep 예시

기본 구성 자체는 PCIe 또는 Storage가 critical path이므로 DRAM BW만 바꾸어도 결과가 변하지 않습니다. 이는 모든 부품 향상이 항상 성능 향상으로 이어지지 않는다는 bottleneck 모델의 의도된 결과입니다.

| Scenario | TTFT (ms) | TPS | Prefill path | DRAM cache (GB) | VRAM cache (GB) |
|---|---:|---:|---|---:|---:|
| Baseline | 37819.9 | 1.755 | PCIe | 67.50 | 6.41 |
| SSD 0.5x | 62066.1 | 1.049 | Storage | 67.50 | 6.41 |
| SSD 2x | 37697.9 | 2.097 | PCIe | 67.50 | 6.41 |
| PCIe 0.5x | 75296.8 | 1.167 | PCIe | 67.50 | 6.41 |
| PCIe 2x | 31157.1 | 2.032 | Storage | 67.50 | 6.41 |
| RAM 64GB | 63525.3 | 1.398 | Storage | 16.30 | 6.41 |
| RAM 256GB | 37737.1 | 2.115 | PCIe | 169.90 | 6.41 |
| VRAM 16GB | 31186.1 | 1.988 | Storage | 67.50 | 14.41 |

이 표의 절대값은 calibration 결과가 아니라 deterministic synthetic workload의 근사치다. 부품 비교에는 동일 모델/워크로드에서 한 변수씩 바꾼 상대 변화만 사용해야 한다.

## 남은 모델 위험

- Prompt Expert working set과 reuse는 synthetic Zipf aggregate다.
- Prefill의 SSD→DRAM→GPU 흐름은 pipeline critical-path 근사이며 per-request event trace가 아니다.
- GPU VRAM bandwidth와 kernel-level compute는 직접 계산하지 않는다.
- Aggregate capacity는 arrival/scheduler/continuous batching을 포함하지 않는다.
- 실제 정확도 평가는 routing trace, kernel latency, SSD QD service curve가 추가된 뒤 수행해야 한다.
