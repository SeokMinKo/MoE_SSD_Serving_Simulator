# V1.4 Hardware Sensitivity Corrections

## Problem and current behavior

V1.3 can show storage-bound decode trends, but several paths distort hardware
sensitivity:

- pinned Experts can be redundantly prefetched;
- storage queue depth is applied twice;
- DRAM hits do not populate the VRAM LRU;
- prefill is an analytic constant that neither warms caches nor responds to all
  relevant hardware paths;
- physical RAM and VRAM do not automatically change Expert cache budgets;
- Swap-in bytes are counted twice in DRAM traffic;
- aggregate TPS can be mistaken for a concurrent serving simulation.

## Goal and success signals

The simulator shall remain an aggregate trend model, while producing
directionally consistent single-request TPS and TTFT changes when SSD, PCIe,
DRAM, compute, RAM, VRAM, and cache placement inputs change.

## Scope fence

- Included: Colibri storage/cache/prefill timing, automatic cache placement,
  regression tests, UI labels, validation documentation.
- Unchanged: deterministic routing seed, AFM aggregate execution model, memory
  pressure state machine, browser-only zero-dependency delivery.
- Excluded: page-level OS VM emulation, real GPU kernel benchmarking, continuous
  batching scheduler, exact production TPS/TTFT prediction.

## Requirements

| ID | Observable rule | State |
|---|---|---|
| REQ-001 | An Expert already present in the pinned store or a faster tier creates no Demand or Prefetch storage read. | IMPLEMENTED |
| REQ-002 | Storage latency waves equal `ceil(request_count / queue_depth)` and are applied exactly once. | IMPLEMENTED |
| REQ-003 | A host-sourced Expert transferred to a discrete GPU is admitted to the VRAM LRU after transfer completion. | IMPLEMENTED |
| REQ-004 | Colibri prefill warms Expert caches and TTFT is the maximum of compute, storage/PCIe, and DRAM prefill paths plus first-token TPOT. | IMPLEMENTED |
| REQ-005 | Auto Placement derives DRAM/VRAM Expert cache budgets from capacity after fixed weights, KV, workspace, OS/background use, and headroom. | IMPLEMENTED |
| REQ-006 | A Swap-in byte contributes once, not twice, to token DRAM traffic. | IMPLEMENTED |
| REQ-007 | Aggregate TPS is displayed and documented as a capacity upper bound, not a scheduler or continuous-batching prediction. | IMPLEMENTED |

## Contracts and invariants

- INV-001: Full Expert residency implies zero Colibri Expert Demand and
  Prefetch storage traffic.
- INV-002: Increasing Auto Placement RAM or VRAM cannot reduce the corresponding
  cache budget.
- INV-003: Configured DRAM throughput remains a roofline; measured token DRAM
  throughput cannot exceed it.
- CON-001: Manual Placement preserves the explicit `dcache` and `vcache` inputs.
- CON-002: Auto Placement never allocates more than the model Expert pool and
  never uses negative capacity.
- INV-004: Populated discrete-device cache, KV, and workspace usage cannot
  exceed configured VRAM without reporting Device OOM.

## Acceptance examples

- SCN-001: Given every routed Expert is pinned, when decode and prefetch run,
  then Expert Demand and Prefetch bytes are both zero.
- SCN-002: Given eight independent storage requests, when QD changes from 1 to
  2 to 4 to 8, then latency waves are 8, 4, 2, and 1.
- SCN-003: Given a cold prompt, when prefill completes, then the first decode
  token observes warmed Expert tiers and TTFT changes when the active hardware
  critical path changes.
- SCN-004: Given Auto Placement, when RAM or VRAM increases with all other
  inputs fixed, then its derived cache budget does not decrease.

## Test and observability plan

- Strategy: inside-out; deterministic Node component tests execute the actual
  browser simulation modules without external doubles.
- Working suite: `node --test tests/simulator.test.cjs`
- Commit suite: working suite, `node --check` for every JavaScript module, and
  browser Self-test.
- Observability: existing result counters are extended with Prefill path
  breakdown, effective placement, and VRAM promotion count. No external logging
  is introduced.

## Implemented approximation

- Prefill unique Expert count uses prompt length, active Experts, concurrency,
  and the same Zipf exponent as decode routing.
- Repeated prompt activations use the Zipf mass covered by the derived cache
  capacity to estimate SSD and PCIe reloads.
- Auto Placement targets the hard threshold for Strict mode and the soft
  pressure threshold for reclaim/swap modes.
- Manual Placement retains its explicit budgets, but populated device usage is
  still checked against physical VRAM.
- Prefill paths are treated as aggregate pipelines; their maximum, rather than
  their sum, is exposed as the critical path.

## Risks and rollback

- Auto Placement changes default results. Manual mode remains available as the
  compatibility and rollback path.
- Prefill remains aggregate rather than token-exact. UI and README must retain
  the approximate-trend limitation.
- If an invariant or baseline regression fails, do not publish the affected
  behavior.
