# v1.6.2 Correctness Contract

## Status and scope

v1.6.2 remains **Unvalidated Alpha**. It is suitable for controlled, relative sensitivity experiments. It is not a calibrated predictor of absolute hardware TTFT, TPOT, throughput, or capacity.

This patch changes three contracts only: compressed-KV partial-touch accounting, AFM `totalB` classification, and shared input limits. The concurrency, batching, storage-service, compute, and DRAM roofline models remain unchanged.

## Compressed KV partial-touch invariant

At token start, decompression work is based on original, uncompressed bytes:

```text
decompressed_original_GB =
    pre_existing_resident_compressed_original_GB × kvTouchFraction
  + newly_swapped_in_compressed_original_GB
```

`newly_swapped_in_compressed_original_GB` has already been selected by `kvTouchFraction`; the fraction must not be applied to it again. Decompression traffic is:

```text
decompression_traffic_GB =
  decompressed_original_GB × (1 + 1 / compressionRatio)
```

The sum of compressed original bytes in DRAM and swap is conserved across the touch. The corresponding physical stored bytes are also conserved except for their residency location.

## AFM totalB metadata boundary

AFM `totalB` is capacity metadata. Together with `bits` and `packing`, it computes the displayed whole-model NAND footprint:

```text
totalNandGB = totalB × bits / 8 × packing
```

`totalB` does not change TTFT, TPOT, TPS, active/resident weights, KV memory, swap traffic, or I/O service time. It is therefore excluded from the performance Sweep catalog. The scenario artifact retains it so the displayed storage-capacity estimate is reproducible.

## Shared input limits

The validation, Sweep, and browser input contracts use the same `SIMULATION_LIMITS` values:

| Input | Minimum | Maximum | Rule |
| --- | ---: | ---: | --- |
| `prompt` | 0 | 1,000,000 | safe integer |
| `output` | 1 | 1,024 | safe integer |
| `mem.swapWriteRatio` | 0.001 | 1 | finite ratio |

Direct serving request output counts use the same `output` range.

## Decimal SI units

Every UI/configuration field labeled `GB`, `MB`, or `KB` uses decimal SI units:

- 1 GB = 1000 MB
- 1 MB = 1000 KB
- 1 GB = 1,000,000 KB

Binary units are not implicit. A future binary-valued field must be labeled explicitly as `GiB`, `MiB`, or `KiB` and must not reuse a decimal field.

## Metric populations

- **TTFT:** request arrival through the first completed token, including blocking initial selection, reads, patching, compression, and swap dependencies.
- **TPOT percentiles:** completed decode tokens only; the first-token interval is excluded.
- **Storage/token:** decode storage traffic divided by completed tokens. Startup and predecode traffic are reported separately.
- **Aggregate TPS:** completed tokens divided by the completed-event wall-clock interval for every concurrency value, including one.
- **Peak allocation demand:** pre-policy high-water mark of requested bytes.
- **Peak physical memory:** high-water mark of admitted resident bytes after pressure admission.

## Reproducibility fence

Scenario schema remains `moe-ssd-sim/v4`. Run IDs are fenced by model version `1.6.2`, package version `1.6.2`, commit, build identity, configuration, and request population. The schema is unchanged because the artifact shape is unchanged; corrected calculations are separated by the model/package provenance fence.

Published browser assets must be produced with `npm run build:release` from a clean release commit. The builder records the exact 40-character Git SHA and `release/v<package>+<sha>` identity.

## Known limits unchanged by this patch

- The scheduler and finite request-population throughput definition remain synthetic approximations.
- The fixed batching factor and admission window are not calibrated service curves.
- SSD QD and request-size behavior are not measured storage profiles.
- AFM patch materialization remains excluded from the DRAM byte bound.
- Absolute TTFT, TPOT, and TPS require independent hardware calibration and holdout validation.
